# 教学原则

## 1. 中文讲解，英文术语对照

首次出现的重要术语采用“English Term（中文翻译）”形式，并说明它在工程中的作用。对容易混淆的术语，给出比较和例子。

## 2. 先讲问题，再讲概念

先提出一个真实工程问题，再解释对应技术为什么存在。例如先展示模型无法直接访问业务数据库的问题，再引出 Tool Calling，而不是只给出定义。

## 3. 原理与场景并重

复杂概念至少解释：

- 它是什么。
- 它解决什么问题。
- 它在系统中如何工作。
- 适合什么场景。
- 不适合什么场景。
- 与相近方案有什么区别。
- 生产环境中有哪些风险。

## 4. 核心代码必须可运行

代码示例应尽量提供：

- 文件结构和完整关键文件。
- 依赖安装命令。
- 环境变量配置示例（不得包含真实密钥）。
- 启动命令和请求示例。
- 预期输出。
- 常见错误及排查方式。

不以模拟 Python 片段代替真实模型调用、真实工具执行或关键框架流程。需要外部 API、API Key、数据库或容器环境时，明确写出前置条件。

## 5. 从最小实现逐步扩展

先实现最小可用版本，再逐步加入校验、异常处理、持久化、安全、评测和部署。避免第一节就引入过多框架。

## 6. 解释完整执行链路

不仅解释每行代码，还应讲清：

- 请求从哪里进入。
- 模型收到什么消息。
- 模型如何提出工具调用。
- 应用程序如何校验并执行工具。
- 结果如何返回模型。
- 状态如何更新。
- 系统如何结束、失败、暂停或恢复。

## 7. 每节课的固定结构

1. 学习目标
2. 前置知识
3. 核心术语（英文 + 中文）
4. 原理与执行流程
5. 适用场景与方案比较
6. 可运行代码
7. 运行步骤与预期结果
8. 逐步解释关键代码
9. 项目实践
10. 测试与异常场景
11. 练习任务
12. Summary（本节总结）
13. 面试题与参考答案（每节 3–5 题）

## 8. 面试能力贯穿课程

每节都配套面试题，题型包括：

- 基础概念与原理。
- 技术方案比较。
- 代码执行机制。
- 故障排查。
- 系统设计与项目深挖。

参考答案要解释“为什么”，而不是只给背诵句子。

## 9. 持续复盘

每周记录已掌握内容、尚不理解的概念、代码问题、架构决策和下周目标。重要架构决策记录到 `docs/architecture-decisions.md`（后续创建）。
