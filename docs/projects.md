# 实战项目规划

## 项目 A：Database Agent

### 目标

构建一个受权限控制的数据库智能体，让用户用自然语言了解数据库结构、查询允许访问的数据，并获得解释清晰的结果。

### 逐步演进

1. 模型 API 对话服务。
2. 结构化需求解析。
3. 只读数据库工具。
4. Schema 元数据读取。
5. Tool Calling 与结果解释。
6. SQL 参数、权限、只读限制、查询超时和行数限制。
7. RAG 检索数据字典、工具说明和业务文档。
8. MCP Server/Client。
9. 用户、团队与资源权限边界。
10. 评测、追踪、成本统计与部署。

### 安全边界

- 初始阶段只连接测试数据库。
- 默认使用只读数据库账号。
- SQL 检查只是纵深防御之一，不能替代数据库权限。
- 限制可访问的 Schema、表、列、查询时长和返回行数。
- 对敏感字段实施授权、脱敏和审计。
- 任何写入、删除或有明显副作用的操作均不作为初始课程默认能力。

## 项目 B：AI4S Workflow Agent

### 目标

构建科研分析任务的端到端执行原型，包含任务规划、人工审核、工作流执行、结果展示和可复用流程沉淀。

### 建议流程

1. 用户描述科研分析需求。
2. Agent 生成任务计划和必要参数。
3. 后端校验计划的结构与可执行范围。
4. React Flow 展示任务步骤、依赖和状态。
5. 科研人员审核或修改计划。
6. LangGraph 管理任务状态与执行路径。
7. 调用受控的分析工具或 Nextflow 工作流。
8. 收集日志、产物和错误信息。
9. 生成结果摘要与可追溯报告。
10. 经人工审核后，将流程保存为可复用 Pipeline。

### 工程关注点

- 将任务计划、执行实例和 Pipeline 模板区分开。
- 记录输入、参数、工具版本、执行状态和输出产物。
- 支持暂停、失败、重试与恢复。
- 不允许模型直接绕过权限系统执行任意命令。
- 对文件路径、计算资源、外部工具和数据访问进行限制。
- 结果报告应注明数据来源、执行参数和失败情况。

## 两个项目的关系

Database Agent 负责在前期训练工具调用、元数据、检索和权限能力；AI4S Workflow Agent 用于综合训练规划、状态机、人工审核、工具执行、评测与部署。通用 Agent 技术不局限于生物信息学。
