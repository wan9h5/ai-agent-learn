# 学习方法

## 核心方法：知识点驱动的项目式学习

不是先看完所有理论再做项目，而是每学一个知识点，就将它接入持续演进的项目。

学习循环：

1. 明确本节要解决的实际问题。
2. 学习概念、原理和适用场景。
3. 先跑通最小可运行示例。
4. 阅读代码并解释完整执行链路。
5. 将知识点接入 Database Agent 或 AI4S Workflow Agent。
6. 编写测试，主动触发异常场景。
7. 完成本节 Summary、练习和面试题。
8. 记录遇到的问题、架构决策与尚未理解的概念。

## 每节课的完成标准

不能只以“代码运行了”作为完成标准。至少应做到：

- 能用自己的话解释核心概念。
- 能从入口开始讲清楚数据流和控制流。
- 能独立修改一个关键参数、工具或节点。
- 能解释常见失败情况以及处理方式。
- 能完成一道动手练习。
- 能回答本节至少 3 道面试题中的核心问题。

## 理论与实践比例

建议大致采用：

- 30%：概念、原理与官方文档。
- 50%：编码、调试和项目集成。
- 20%：测试、复盘和面试练习。

比例可随主题调整。例如 LangGraph 状态管理需要更多实践；LLM 基础概念则需要较多解释与比较。

## 学习节奏

每周安排 3 节课：

- 第 1 节：建立概念并实现最小示例。
- 第 2 节：深入执行机制，加入测试与异常处理。
- 第 3 节：集成到项目，完成复盘和面试题。

建议每周投入 8–10 小时。若每周不足 5 小时，可把 12 周路线延长到 16–20 周。理解和工程质量优先于赶进度。

## 学习资料使用顺序

1. 本课程的中文讲解与实战代码。
2. 对应框架的官方文档。
3. 官方示例和高质量工程案例。
4. 必要时再阅读论文或社区讨论。

不要机械照抄教程。需要理解框架解决了什么问题、引入了什么抽象，以及不用框架时如何实现同一流程。
